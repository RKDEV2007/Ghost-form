РЕЧЬ НА ЗАЩИТУ — «GHOST FORM STAGE»

============================================
ДОКЛАДЧИК 1 — слайды 1, 2, 3  (~2 мин)
============================================

Здравствуйте!

Мы представляем наш проект — Ghost Form Stage.
Это браузерная игра, которую мы сделали для обучения основам
веб-безопасности.

[СЛАЙД 1]

Идея появилась из простого наблюдения: про CSRF и XSS написано много,
но прочитать про атаку и попробовать её остановить — это разные вещи.
Мы хотели сделать что-то, где можно именно попробовать.

[СЛАЙД 2]

Поэтому мы сделали игру, в которой игрок становится сисадмином.
На его сервер приходит подозрительный трафик — он должен разобраться,
что происходит, и заблокировать угрозу.

Никакой теории — только действие. Увидел в логах подозрительный POST,
открыл редактор кода, добавил защиту, проверил результат.

[СЛАЙД 3]

Игра разбита на 5 дней. Каждый день — отдельная тема:

  Первый день  — CSRF-токены
  Второй       — работа с сессиями
  Третий       — проверка Origin и SameSite
  Четвёртый    — DOM-инъекции
  Пятый        — финал: три варианта решения, три разные концовки

Через весь сюжет ведёт персонаж Хлоя — она объясняет, что происходит,
и направляет, что делать дальше.

ДОКЛАДЧИК 2 — слайды 4, 5, 6  (~3 мин)
============================================

[СЛАЙД 4]

Покажу, как выглядит интерфейс.

Экран разделён на три рабочие зоны.
Слева — навигация: ЛОГИ, INSPECT и ФОРМА.

  В ЛОГАХ видно серверные запросы — именно здесь появляется
  «призрачный» POST, который игрок должен заблокировать.

  В INSPECT находится редактор кода — HTML или JavaScript.
  Здесь игрок вписывает защиту: CSRF-токен, конфиг, нужные поля.

  В ФОРМЕ можно отправить запрос самому и посмотреть,
  как сервер на него ответит.

Справа — список задач. Вверху — статы: жизни, концентрация, безопасность.

[СЛАЙД 5]

Отдельно хочу рассказать про туториал, который мы реализовали
по техническому заданию.

При первом запуске игры показывается обучающий экран:
слева портрет Хлои, справа — объяснение каждого раздела интерфейса.

После закрытия запускается интерактивный гид — четыре шага:

  Первый шаг:  подсвечивается ЛОГИ — игрок открывает, видит запросы
  Второй:      подсвечивается INSPECT — открывает, видит редактор
  Третий:      подсвечивается ФОРМА — открывает, видит поля
  Четвёртый:   первое задание в редакторе — написать <input> в HTML

Это сделано, чтобы игрок не терялся с первых секунд.
Туториал показывается только один раз и не повторяется при загрузке.

[СЛАЙД 6]

По технической части.

  Фронтенд: React 19 и Vite 8, стили — чистый CSS без фреймворков.
  Состояние: useReducer и Context API — без Redux и лишних зависимостей.
  Бэкенд: Express 5, REST API для сохранений.
  Хранение: localStorage и JSON-файл на сервере.

Теперь про то, как именно работает редактор в INSPECT —
это самая интересная часть с точки зрения реализации.

Игрок вводит текст в обычный textarea — это обычный HTML-элемент,
в котором можно писать что угодно. Когда он нажимает «Проверить код»,
мы берём этот текст и прогоняем через функцию validateCode.

Внутри неё — регулярные выражения. Для первого дня, например,
мы проверяем два условия: в коде должен встречаться атрибут type="hidden"
и name="csrf_token". Именно так выглядит правильный CSRF-токен в HTML.
Если оба условия выполнены — ответ принят. Если нет — выдаётся ошибка
и снимается жизнь.

Для каждого дня — свои регулярки и своя логика.
В день второй проверяем, что игрок правильно написал имя сессии.
В день третий — что он заполнил три конкретных поля конфига.
В день четвёртый — что удалил вредоносные теги и добавил токен.

При успехе функция обновляет состояние игры через reducer:
меняются флаги, в серверные логи добавляется новая запись
с пометкой «blocked», игроку начисляются очки.

То есть вся «магия» — это строковый парсинг через regex.
Просто, но работает именно так, как работает реальная серверная валидация —
там тоже проверяется наличие нужного параметра в запросе.

Три момента из архитектуры, которые стоит отметить:

  Первый — гайд-система на событиях. Каждый шаг гайда срабатывает
  по конкретному действию игрока: открыл нужную вкладку — шаг пройден.
  Это сделано через паттерн «completeOn».

  Второй — синхронизация сохранений. Если есть конфликт между локальным
  и серверным сохранением, побеждает то, у которого свежее время.

  Третий — таймер концентрации. Каждые 12 секунд в фоне срабатывает
  интервал и уменьшает счётчик. Это создаёт давление — нельзя просто
  сидеть и думать бесконечно.

[ДЕМОНСТРАЦИЯ — перед слайдом 7]

Давайте покажу игру вживую.

[Открыть localhost:5173]

Вот стартовый экран. Жмём играть, проходим вступительный диалог.

[IntroVN → GameScreen → TutorialModal]

При первом запуске появляется туториал: Хлоя объясняет интерфейс.
Жмём «Приступить к работе» — запускается интерактивный гид.

[Пройти шаги 1-4: открыть Логи, Inspect, Форму, написать input]

Видно, что каждая вкладка подсвечена — игрок не может случайно
пропустить шаг. В четвёртом шаге нужно самостоятельно написать
тег input в редакторе.

[После туториала — начало дня 1]

Начинается первый день: в логах появляется Ghost POST без CSRF-токена.
Переходим в INSPECT, добавляем строку с csrf_token, нажимаем «Проверить».
Возвращаемся в ЛОГИ — новый Ghost POST теперь заблокирован.

[СЛАЙД 7]

По тестированию. Мы проверяли основные сценарии:

  Туториал показывается при первом запуске и не повторяется повторно.

  Интерактивный гид работает по порядку: нельзя открыть следующий шаг,
  не завершив текущий.

  В четвёртом шаге туториала — валидация: без тега input выдаётся ошибка.

  День 1 проходится полностью: Ghost POST → INSPECT → заблокирован.

  При неверном коде — жизни уменьшаются.

  Прогресс сохраняется после обновления страницы.

  Все три финала дают разный текст концовки.

[СЛАЙД 8]

Что в итоге получилось:

  Рабочая игра — 5 дней, 3 концовки, система сохранений.
  Туториал с интерактивным гидом и заданием в коде.
  Игрок сам пишет HTML и видит, как меняется поведение сервера.
  Нет сторонних UI-библиотек — всё написано вручную.

Если продолжать развивать проект — можно добавить XSS и SQL,
таблицу результатов и мобильную адаптацию.
